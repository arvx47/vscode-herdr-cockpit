How to read the Herdr Cockpit sidebar

The sidebar is a live view of your Herdr server: every space, the agents and shells in it, and what each one is doing. Nothing runs inside the editor. Agents and shells keep running in Herdr, and the terminal tabs Herdr Cockpit opens are live views of Herdr's panes. Works in VS Code, Cursor, Kiro and Positron, on macOS and Linux.

Getting started

  1. Open the Cockpit window. A window opened without a folder (a new window, or the editor's first launch) asks Working with agents?: click Open Herdr Cockpit. Or use → Set Up Cockpit Window. The Cockpit window is made for Herdr: its first folder never changes, so switching spaces never restarts your extensions (see the Cockpit window).
  2. Make sure Herdr runs. If it doesn't, the sidebar offers Start Herdr (see When Herdr isn't running).
  3. Click a space. Its folder opens in the window and every agent and shell opens as a terminal tab.
  4. Optional: the Herdr plugin jumps here from Herdr in your terminal, and Show plan limits… in Usage adds Claude Code's limits.

The same steps are in the Get started with Herdr Cockpit walkthrough (Command Palette: Welcome: Open Walkthrough…).

Create, rename and close

New space (next to "Spaces")
Pick Choose a folder…, or New git worktree of an existing space: a separate checkout on a new branch, so an agent can work without touching your current branch (Herdr puts it in ~/.herdr/worktrees/<repo>/<branch>). Then name it and choose what to start. The window switches to the new space.
New tab (bottom of a space card, or right-click a space)
Choose Shell, Shell with a name… or an agent. The agents listed first come from the herdr.agents setting; More agents… lists every agent Herdr can start. The tab opens right away; an agent starts in it in the background (a notification shows progress).
The terminal's and Split Terminal buttons
In the Cockpit window, a plain + creates a Herdr shell tab in the current space: the space of the terminal you're in, else the space mounted in the window, else the one focused in Herdr. Its dropdown has Herdr Shell, Herdr: Claude, Codex, Kiro, Cursor and Other Agent…, plus your normal local shells. In other windows the Herdr entries are in the dropdown only. Split Terminal on a Herdr tab splits that pane in Herdr, next to it in the same Herdr tab (in the editor area; in the bottom panel a split creates a new Herdr tab). If Herdr isn't reachable, + opens a local shell.
Rename… (right-click)
Spaces take any name. Shells too (empty = use the tab name). Agent names are identifiers in Herdr: lowercase letters, digits, - and _ (for example reviewer). The open terminal tab is renamed as well. Renaming the terminal tab itself (right-click the tab → Rename) does the same in Herdr.
Close in Herdr… (right-click)
Stops the shell or agent, or a whole space, after asking. (Closing a terminal tab with its X does this too: see Terminal tabs.) For a worktree space you can also delete its worktree folder; Herdr refuses if it has uncommitted changes and asks before forcing it.

Herdr can report an agent as started even when that agent isn't installed. If a new agent tab shows "command not found", install the agent's CLI first.

Terminal tabs

  • Click any agent or shell row to open it in a VS Code terminal tab. The tab has the same name as the row and the agent's logo as its icon. Clicking again brings the existing tab forward.
  • Agents open with takeover: your keystrokes go to the agent from this tab.
  • One client controls a pane at a time. When another one takes it (a Cockpit window in another editor, or herdr attach in a terminal), the tab keeps showing the pane live but read-only, with a yellow note on its bottom row saying who has it, for example Kiro is using this pane · type here to take it back. The first key you press takes control back; that key isn't sent, so it can't answer an agent's question by accident. Selecting and copying still work while it's read-only. A notification says which panes were taken, with Take Back (setting herdr.notifyOnTakeover). Clicking the pane or its space in the sidebar takes it back too.
  • Selecting and copying text works like the Herdr TUI: drag to select, double-click a word, triple-click a line. The text is copied when you let go: a green Copied to clipboard note flashes at the bottom of the tab, and the status bar says how many characters. Keep dragging past the top or bottom of the tab and it scrolls the pane's scrollback for you, selecting as it goes (faster the longer you hold). The mouse wheel scrolls the scrollback too.
  • Deleting selected text: select part of the line you're typing (a shell command, or the input of Claude Code or Codex) and press Backspace or Delete. The tab moves the cursor to the end of the selection and erases it, like an editor. Typing replaces the selection the same way. It works on one line at a time; elsewhere Backspace does what it always does.
  • Option+click (Alt+click) on the line you're typing moves the cursor there. Shift+click extends a selection (macOS).
  • Find (⌘F / Ctrl+F) searches the pane's whole history in Herdr, not just the screen. A bar on the top row shows the count (3 of 57); every match on screen is highlighted and the current one stands out. Enter or ↑ goes to the older match, ↓ to the newer one (also ⌘G / ⇧⌘G, F3 / Shift+F3); each jump scrolls Herdr so the match is in the middle. Tab lists every matching line: type to filter, move through it to preview, Enter to stay. Esc closes the bar and leaves the view where it is; typing returns to the bottom. Lower-case queries ignore case, a capital makes it exact, and /…/ is a regular expression.
  • Scrolling the history from the keyboard: Shift+PageUp / Shift+PageDown, and ⌘Home / ⌘End (Ctrl+Home / Ctrl+End) for the top and the bottom.
  • Open Terminal Output in Editor (right-click in the tab, or the Command Palette) opens the pane's whole history as a document, to search and select with the editor.
  • ⌘+click (Ctrl+click) a file path such as src/app.ts:42 to open it at that line, beside the tab. Paths are resolved from the pane's folder.
  • Right-click opens the editor's terminal menu (with Find and Open Output). Selected text is already copied when you let go; to make right-click paste, set terminal.integrated.rightClickBehavior to paste.
  • A click without dragging goes to the program in the pane (Herdr 0.9.2 or newer), so buttons in mouse-aware programs such as Kiro still work.
  • Herdr Cockpit draws these tabs from Herdr's live stream of the pane; there is no shell inside them, so every key goes straight to the agent or shell in Herdr.
  • Closing a tab with its X closes it in Herdr too (setting herdr.closeTabInHerdr). An idle shell closes right away. For an agent, a shell that's running something, or a space's last tab (Herdr then closes the space), it asks first: Keep Running leaves it in Herdr. Switching spaces, and closing or reloading the window, never close anything in Herdr: those tabs only detach.
  • The terminal + creates a new tab in the current Herdr space, and Split Terminal on a Herdr tab splits that pane in Herdr (in the editor area; in the bottom panel a split makes a new Herdr tab). A pane you close in Herdr closes its tab here.
  • Renaming a tab (right-click → Rename) renames the shell's pane in Herdr, or the agent (agent names become lowercase, like reviewer-bot). A pane renamed in Herdr renames its tab here within a few seconds.
  • In the Cockpit window, tabs show only their name. Elsewhere VS Code adds the folder name after it; to hide that in every window, set terminal.integrated.tabs.description to ${task} in your user settings.
  • Clicking a space opens all its panes as tabs, in order: agents (most urgent first), then shells.
  • Switching spaces closes the previous space's tabs (setting herdr.closeTerminalsOnSwitch). Tabs open in the editor area, the editor area split into agents (left) and shells (right), or the bottom panel (herdr.terminalLocation).

Status bar, badge and alerts

  • Status bar (bottom left): agent count, then working , blocked and done counts. It turns yellow when something is blocked. Click it to jump to the agent that needs you. Herdr means Herdr isn't connected: click it for Start Herdr, Open Herdr TUI, Retry and Copy Diagnostics.

Follow mode and the Cockpit window

Follow mode ( menu → Follow Herdr Focus): when you switch spaces in Herdr itself, this window switches too. To avoid hijacking unrelated windows it only acts in the Cockpit window, or in a window where you've already switched a space from the sidebar.

The Cockpit window ( menu → Set Up Cockpit Window) is a dedicated VS Code window for Herdr. Its first folder never changes, so switching spaces never restarts your extensions. In the Cockpit window, terminal tabs show just their name, and VS Code's terminal + creates Herdr tabs (see Create). The first time a Cockpit window opens, it opens this sidebar for you. The Cockpit window opens without the editor's Welcome page, and opening a space closes it in any window.

Cockpit windows in several editors (say VS Code and Kiro) can follow Herdr at the same time. When they follow the same space switch, a pane another window already has stays with that window and shows here read-only (see Terminal tabs); type in its tab to take it.

A window opened without a folder (a new window, or the editor's first launch) asks whether to open Herdr Cockpit there (setting herdr.offerHubOnStartup; Don't Ask Again turns it off). It doesn't ask when a Cockpit window is already open.

Clicking a space in any other window asks first: switching spaces there would make it an untitled workspace (or add folders to your own workspace). Open Cockpit Window opens that space in the Cockpit window instead; Use This Window switches here, and the window remembers your choice. A window with no folder always uses the Cockpit window.

Open selected file in editor prefix+shift+o
Select a location in any pane (src/app.ts:42:7, app.ts(42,7), app.ts#L42, a Python traceback line) and it opens here at that line.

When Herdr isn't running

Your spaces and agents live in the Herdr server, so without it the sidebar has nothing to show. It says why and offers the next step:

The sidebar saysWhat to do
Herdr isn't runningStart Herdr starts the server in the background, with no window and with a terminal-like environment (VS Code's own variables aren't passed on to your panes). It keeps running after you quit VS Code, so your agents keep running too; stop it with herdr server stop. Open Herdr TUI runs Herdr's full interface in an editor tab instead.
Herdr stopped unexpectedlyIt crashed and left its socket file behind. Start Herdr is safe: Herdr restores your spaces, tabs and folders. Agents with a Herdr integration (such as Claude Code) resume their sessions; others come back as shells.
Herdr isn't installedInstall Herdr opens herdr.dev. If it is installed somewhere unusual, set herdr.binaryPath (user settings).
This Herdr version isn't compatibleHerdr and Herdr Cockpit speak different protocol versions: update Herdr (herdr update) or Herdr Cockpit.
Herdr isn't answeringThe server runs but doesn't respond: Retry, or Copy diagnostics for a bug report.
Opening the Cockpit window with Herdr stopped
The first time, Herdr Cockpit asks whether to start Herdr whenever the Cockpit window opens: Always Start Herdr, Not Now (ask again next time) or Never. Change it later with the herdr.startServer setting. Herdr Cockpit never starts a second server for a session that already has one.
Short interruptions
If the connection drops briefly (for example while Herdr updates), the sidebar keeps the last view, greyed out, with Reconnecting to Herdr…. It reconnects by itself: right away when Herdr's socket reappears, when you focus the window or open the sidebar, and otherwise every few seconds (backing off to 10 s).
If Herdr stops while you work
You get one notification (your agents stopped with it), the status bar shows Herdr, and the badge is cleared. Open terminal tabs keep their last screen with a note that the stream ended; close them, or let Herdr Cockpit reopen them when Herdr is back.
When Herdr is back
Herdr Cockpit offers Reopen the tabs for the space you had open. That replaces the ended tabs with fresh ones (pane ids change when Herdr restarts, so it finds the space by name).
Meanwhile
VS Code's terminal + opens ordinary local shells (it tells you once). New Space and New Tab offer to start Herdr first.
Copy diagnostics
Copies Herdr Cockpit's and VS Code's versions, the herdr path and socket path it uses, Herdr's own status report and the connection state, for a bug report. It includes local file paths, so check it before sharing.

Settings

Privacy and safety

  • Everything shown comes from your Herdr server and from files on this machine. Shell output, agent screens and usage numbers never leave your computer. The only network request is Codex's own usage check, which Codex makes with its own login.
  • Herdr Cockpit never reads the agents' logins or tokens. Claude's plan limits come only from the status line you opt into.
  • The git line runs only in trusted VS Code windows (Workspace Trust is the safety boundary, as for VS Code's own git support). On top of that, every git call switches off the commands a repository can define for itself that are known to run during a status check (fsmonitor, file filters, signature checks, hooks, fetching), and skips the folder entirely if it can't. Only trust windows you'd let run code from the repositories in your spaces.
  • herdr.binaryPath and herdr.socketPath count only in your user settings: a repository's own settings can't choose the program Herdr Cockpit runs.

Troubleshooting

A tab says another window or client "is using this pane"
Another client took the pane over: a Cockpit window in another editor (it says which), another window of this editor, or something else such as herdr attach ("another Herdr client"). Herdr lets only one of them type into a pane. The tab stays live, read-only: type in it to take the pane back. To stop two editors from taking panes from each other, keep one Cockpit window, or turn off Follow Herdr Focus in the one you aren't using.
Terminal tabs open in another editor group
Herdr tabs open next to the Herdr tabs already open, else in the group they used last, else in the active group. To move them, drag a tab to the group you want. herdr.terminalLocation = editorSplit puts agents on the left and shells on the right.
Terminal tabs show a folder name after their name
The editor adds the terminal's folder to each tab, and it can't be turned off per terminal. Herdr Cockpit turns it off for the Cockpit window, and for any saved or untitled workspace you've switched spaces from (reload the window if it was already open). In a window with a single folder it leaves your repository's settings alone: to hide it everywhere, set terminal.integrated.tabs.description to ${task} in your user settings.
Herdr Cockpit's tab is last in the sidebar (Positron, Kiro)
Editors don't let extensions choose their tab's position. Drag the Herdr Cockpit tab to where you want it; the editor remembers the order.
Can't find the Herdr Cockpit sidebar (Cursor and other editors)
Open it from the Command Palette: Herdr Cockpit: Focus on Spaces & Agents View. Cursor shows its activity bar as a row of icons across the top of the sidebar, and icons that don't fit sit behind the ⌄ arrow at the end of the row. Once the sidebar is open, right-click the icon row to keep Herdr Cockpit visible, or drag it to the other side of the window.
"Working with agents?" appears in every new window
It asks in windows opened without a folder, unless a Cockpit window is already open. Click Don't Ask Again, or set herdr.offerHubOnStartup to never (or allWindows to be asked in every window).
The Welcome page doesn't close
Herdr Cockpit recognizes it by its English title ("Welcome", "Get Started"); with the editor in another language it stays open. Close it once, or set workbench.startupEditor to none.
The sidebar says Herdr isn't running, installed or answering
See When Herdr isn't running. If you use a named Herdr session or a custom socket, set herdr.socketPath (user settings).
Explorer says "Untitled (Workspace)"
A window becomes an untitled workspace when a space's folder is mounted next to the folder it already had. Use the Cockpit window instead (Set Up Cockpit Window), or save this one with File → Save Workspace As….
A terminal tab won't open
VS Code may not find the herdr binary when it was started from the Dock or an app launcher, which don't load your shell's PATH. Set herdr.binaryPath in your user settings (workspace values are ignored).
Agents show up as shells running "zsh (kiro-cli-term)"
Kiro's shell integration wrapped Herdr's pane shells, which hides agents from Herdr. It happens when the Herdr server was started without Kiro's terminal around it (older Herdr Cockpit versions' Start Herdr did this). The agents are still running. Stop Herdr (herdr server stop) and click Start Herdr again: panes then start without the wrapper, and agents with a Herdr integration resume.
No git line under a space
The folder isn't a git repository, or the window isn't trusted (Manage Workspace Trust in the Command Palette).
An agent is missing from Usage
Usage lists only Claude Code, Codex and Kiro, and only while one of their panes is open in Herdr.
Claude Code shows no bars
Click Show plan limits…. Bars need a claude.ai Pro or Max plan and appear after Claude's next reply.
Codex shows "as of …" instead of "live"
The live check couldn't reach Codex (not installed where VS Code looks, or logged out); the numbers come from its logs instead.
Something looks wrong
Right-click it → Show Raw Herdr Record, or → Show Raw Session Snapshot. The Herdr Cockpit output panel logs connections and follow-mode switches.
