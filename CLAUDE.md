# Herdr Cockpit — VS Code extension (formerly Herdr Hub)

## What this is
A VS Code extension that brings [Herdr](https://herdr.dev) (a terminal-native multiplexer for AI coding agents)
into **one** VS Code window. Goal: keep Herdr's spaces/agents workflow but get the VS Code IDE
(files, diffs, SCM) without juggling a terminal app plus several VS Code windows.

The user runs Herdr in the macOS terminal. Their agents include Claude Code, Codex and Kiro. The extension is a **client of the
Herdr server**. It never owns agent processes; Herdr does.

Status: v0.1.0 (first release, tagged 2026-10-06), installed and tried by the user on macOS against a real Herdr
server (installed binary: herdr 0.9.5 on 2026-11-10; 0.9.3 since 2026-10-06, upgraded from 0.9.1 with `herdr update --handoff`, which kept all panes and agents; socket protocol 22 in all of them; 0.9.5's schema generates the same types as 0.9.3). Confirmed working in real use: sidebar lists real
spaces/agents, space switching, attach terminals.

## Commands
```bash
npm install
npm run compile        # tsc -> out/, then the sidebar: tsc -p tsconfig.webview.json (check) + esbuild -> media/sidebar.js
npm test               # mock Herdr socket server tests + git info test (no VS Code needed)
npm run package        # -> herdr-cockpit-<version>.vsix
npm run install-local  # package + install in the default VS Code profile and every profile that has it
```
Debug: open this folder in VS Code, press F5 (`.vscode/launch.json`) to get an Extension Development Host.
After installing a new vsix: Command Palette → "Developer: Reload Window".
Bump `version` in package.json for each vsix you hand to the user.
README images (`docs/images/*.png`): `docs/screenshots/render.sh` rebuilds them from the throwaway `hb-demo` session
(see `docs/screenshots/README.md`). Re-render after visible sidebar changes. `docs/**` is kept out of the vsix; vsce
points the store README's images at GitHub, so they show on the Marketplace and Open VSX after the next release.

## Architecture (src/)

| `herdrClient.ts` | Herdr socket API client. NDJSON over a Unix socket. `request()` uses one short-lived connection per call. `subscribe()` keeps a connection open for `events.subscribe`. Resolves the socket path the way Herdr does (`HERDR_SOCKET_PATH` → `HERDR_SESSION` → `~/.config/herdr/herdr.sock`; `sessionSocketPath(name)`). `errorText(e)`: the message of anything thrown (use it instead of `e?.message ?? e`). **No vscode imports** (testable standalone). A line that isn't JSON rejects the pending request (or ends an event stream) instead of looking like a timeout. `subscribe(…, {onAck, ackTimeoutMs})` ends with an error if Herdr doesn't ack within 5s. `expandHome()` (only `~` and `~/`) is shared with connection.ts. |
| `herdrSync.ts` | `HerdrSync`: the connection state machine and sync loop, moved out of `activate()` (0.3.0). States (`Conn`): connecting → connected → reconnecting (keep last view greyed 4s) → down (diagnosed at most every 10s; retry with backoff 1.5s→10s; instant retry via `kick()` on window focus, sidebar shown, socket file appearing via fs.watch). `refresh()` returns the running refresh's promise (a refresh asked for meanwhile runs again inside it, also after a failure, so a `kick()` or the socket appearing during a failing refresh/diagnose retries at once; `eventsLive` is set on Herdr's subscribe ack, so a refused subscription keeps the fast poll), so `kick()` only resolves once the state is current. Subscribes `subscriptionsFor()` the last snapshot's panes and moves the subscription when they change. `beginStarting()`/`endStarting()` around Start Herdr; `socketChanged()` drops the old session's events. ## Key design decisions (keep unless the user says otherwise)
- **VS Code extension as a Herdr client, not a Herdr plugin.** The companion Herdr plugin (`plugin/`) only jumps from Herdr to the editor; all the UI lives in the extension.
- **Hub window:** `Herdr Cockpit: Set Up Cockpit Window` creates `~/.herdr-cockpit/herdr-cockpit.code-workspace`. Slot 0 is `~/.herdr-cockpit`, so switching spaces never restarts extensions. The window is recognized only by its workspace file path (`isHubWindow()`; the `herdr.hubWindow` setting was removed in 0.3.0, old hub files still carry it harmlessly). In the hub, the extension also sets `terminal.integrated.tabs.description` to `${task}` at workspace scope (once, only if unset) so terminal tabs show just their name; VS Code has no per-terminal option for this. Since v0.0.29 `nameOnlyTabs()` also does this in managed windows that have a workspace file (saved or untitled multi-root), never in single-folder windows (it would write the repo's `.vscode/settings.json`), and not if the user set a global value. Sidebar tab order (e.g. Herdr Hub last in Positron's secondary sidebar) can't be set by an extension: the user drags it. The first time a hub window opens it runs `herdr.spaces.focus` once (workspaceState `herdr.hubViewRevealed`): Cursor's horizontal activity bar hides extension icons behind a ⌄ overflow, so users couldn't find the view.
- **Why tabs aren't `herdr attach` (v0.0.31–0.0.34):** `herdr terminal attach` / `agent attach` always enable mouse reporting (`?1000h ?1002h ?1003h ?1006h`, verified with a pty capture on hb-test) and drop drags for programs that didn't ask for the mouse (plain shells, Kiro): no selection, no OSC 52, clipboard unchanged. Attach has no flag to turn this off, and Option+drag (`macOptionClickForcesSelection`) was only a workaround, so tabs are built-in (see herdrStream.ts / termScreen.ts). The Herdr TUI copies by writing the system clipboard itself (no OSC 52). VS Code 1.140 loads xterm's ClipboardAddon unconditionally, so OSC 52 from programs works. An upstream Herdr issue asking for TUI-like selection in direct attach was drafted for the user to file.
- **Window per space (`herdr.windowMode`, default `folder` since the commit "Open each space in its own window by default"):** each space gets a window opened on its folder. Windows record their folders and open spaces (`windows/` in hubFiles.ts), so clicking a space or pane another window has brings that window forward (`openInWindow`, pending link aimed at its folder). For a space nobody has, `askPlacement()` offers its own window or this one, once or always for this window (workspaceState `herdr.placeSpaces`; reset with **Ask Where to Open Spaces Again**). Adding a space to a single-folder window reopens it on a generated workspace file (`reopenWithSpace`) instead of making an untitled workspace. Right-click offers Open in Its Own Window / Add to This Window (spaces) and Attach in Its Space's Window / Attach in This Window (panes): four commands because a menu label is per command. The rules are `decidePlacement()` in placement.ts. The user chose on 2026-11-10 to keep both modes.
- **`herdr.windowMode` = `workspace` (the behavior before, v0.0.30):** `useThisWindow()` runs before every user-started switch outside the hub: a window without folders goes straight to the hub (pending-link hand-off with the space and pane); otherwise a modal offers Open Hub Window / Use This Window (remembered in workspaceState `herdr.useThisWindow`; **Ask Where to Open Spaces Again** clears it too). Follow-mode switches (`fromHerdr`) skip placement (`followsInto()`). `switchTo` returns false when the switch didn't happen here (including a folder VS Code refused to mount), so `attachPane` stops.
- **Follow mode** acts only in a hub window, or after the user has switched a space from VS Code (the `herdr.managedWindow` workspaceState flag). This prevents hijacking unrelated windows.
- **Switching a space:** mount its folder, reveal it in Explorer, call `workspace.focus` in Herdr, and close the attach terminals of other spaces (`closeTerminalsOnSwitch`). Then attach the panes per `herdr.autoAttach` (`all` / `agents` / `none`; replaced `autoAttachOnSwitch` + `autoAttachShells` in 0.3.0, which `autoAttachMode()` still reads until it's set): agents most urgent first (blocked > done > working > idle), then shells in tab order. VS Code places each new terminal tab after the previous one (editor area and panel alike), so they're opened in that order, then the first is focused.
- **Events are invalidation signals.** Always re-read with `session.snapshot`; never apply event payloads incrementally. This is what Herdr's docs recommend: on `events_lost`, resubscribe and re-snapshot.
- **UI layout:** the user moved the Herdr view to the **secondary (right) sidebar** by hand and keeps Explorer on the left. Extensions can't target the secondary sidebar without the proposed API `contribSecondarySidebar` (`viewsContainers.secondarySidebar`), so the container stays in the activity bar.
- **Sidebar design (v0.0.4):** space cards (collapsible, status accent bar, branch/changes line), agents and shells as compact two-line rows (name + status pill, then one line: task/summary or `$ command`) with a chevron that reveals details (summary or screen, output box, chips, folder; persisted per pane in webview state); no "attached" chips, a "Needs you" section for blocked/done agents with a screen preview (only this window's since 0.3.0: agents of a space `here`, or with a tab attached here; `herdr.showNeedsYou` false hides it and frames those rows in their space instead, class `.row.needs`), and a collapsible "Shells" group per space. Pane names come from `paneName()` (viewState.ts) and are used for both the sidebar row and the VS Code terminal tab (VS Code can't rename a tab later, so names use only snapshot fields): agents = display name or kind ("Claude"); shells = pane label → tab label → `Tab N`. Agent terminal tabs use the logo from `media/agent-logos` as their icon. Nothing in `panel.css` assumes the side bar's background (the view can be dragged to the panel, and a webview can't tell where it is): the sticky header is see-through and blurred, and an avatar's status dot sits in a notch cut out of its tile (`::before` with a radial mask) instead of a ring painted in the background color. Space order (`orderByActivity`, setting `herdr.spaceOrder`): busy (working/blocked) first, then last active (an agent's status change after the first snapshot, or the space becoming focused), kept by space **name** in globalState `herdr.spaceActivity`, ties in Herdr's order. The bottom of the webview shows `Herdr Cockpit v<ext> · Herdr <version>` (`ViewState.versions`; not the view's `description`: in the secondary sidebar a single view shows as a tab and the description is dropped, user report on 0.2.5). Space header = chevron + name + agent dots, a New worktree icon on repo cards (shown while hovered or focused, like New tab; `spaceRepo` in the menu context for the right-click entry), plus a visible **Open** button on spaces not `here` (0.3.7: opening a whole space used to be only in the right-click menu); under it the folder line (0.3.9: `~/code/app`, or `app worktree · ~/…/app/out-1`); the git line shows branch · last-commit age · ↑↓/synced/no upstream · conflicts/staged/modified/new or clean · Review. Header: title bar = "Herdr Cockpit" + `?` (help) + `⋯` (Follow Herdr Focus ✓, Open Herdr TUI, Set Up Cockpit Window, Refresh, Settings); the debugging commands (Show Raw Herdr Record, Show Raw Session Snapshot) are in the Command Palette only (0.3.0); webview top = status counters only (the shells toggle moved to `⋯` → Show Shell Panes ✓ in 0.3.7); section order: counters, Needs you (when on), Spaces, Usage (bottom); New space only via the `+` beside "Spaces"; New tab is the row at the bottom of a card, shown while the card is hovered or has focus. Each control lives in exactly one place.

## Herdr API facts used (from herdr.dev/docs/socket-api)
- Socket: `~/.config/herdr/herdr.sock`; named sessions use `~/.config/herdr/sessions/<name>/herdr.sock`.
- Requests look like `{"id","method","params"}\n`. Responses look like `{"id","result"}` or `{"id","error":{code,message}}`.
- Methods used: `session.snapshot`, `events.subscribe`, `workspace.focus {workspace_id}`, `agent.focus {target}`.
- `agent.focus` params are `{target}` (confirmed in the schema). The call is best-effort and errors are swallowed.
- **Notifications (0.3.0):** every window runs the extension (`onStartupFinished`) and sees the same status changes, so `notify()` waits 0ms in the focused window, 300ms in one that has the space, 600ms elsewhere, then `claimNotification()`: only the first window shows it.
- **Jump to Agent Needing Attention** goes through `needingAttention()` from the agent tab you're in to the next, and around.
- Events: `subscriptionsFor(paneIds)` = `DEFAULT_SUBSCRIPTIONS` (parameterless lifecycle events) + one `pane.agent_status_changed {pane_id}` per pane of the latest snapshot; `extension.ts` resubscribes when the pane set changes. Typed against the generated `Subscription` union, so a pane-scoped event without `pane_id` won't compile.
- Pane ids look like `w1:p1`, tab ids `w1:t1`. Ids can change when a pane moves across workspaces.
- Useful extra methods:
  - `agent.prompt` (accepts an optional `wait`), `agent.wait`, `agent.start`, `pane.read`
  - `worktree.create` / `worktree.open` / `worktree.remove`
  - `notification.show`, `layout.export`, `pane.process_info`
- `herdr api schema --json` prints the full JSON Schema of the installed binary; `npm run gen:types` turns it into `src/herdrTypes.ts`.
- `herdr api snapshot` prints a live snapshot.
- Direct attach: only one direct-attach client owns input (`--takeover`). Detach with `ctrl+b q`. On macOS, `ctrl+b` passes through VS Code fine (sidebar toggle is ⌘B there).

## Snapshot facts (from the herdr 0.9.1 schema)
- `session.snapshot` result is `{type: "session_snapshot", snapshot}`. The snapshot is flat: `workspaces`, `tabs`, `panes`, `layouts`, `agents` arrays plus `focused_{workspace,tab,pane}_id`.
- Every agent also appears in `panes`. `AgentInfo` is `PaneInfo` plus `name`, `state_change_seq`, `interactive_ready`, `launch_pending`, `screen_detection_skipped`; only panes have `label` and `scroll`.
- `agent_status` is `idle | working | blocked | done | unknown`; Herdr reports `done` itself. There is **no `seen` field** in the snapshot. Shell panes report `unknown`.
- `tokens` and `state_labels` sit directly on records (no `metadata` wrapper). `WorkspaceInfo` has **no cwd and no branch**; `worktree` (when set) has `checkout_path`, `is_linked_worktree` and repo info. Branch comes from `gitInfo.ts`.
- The two kiro agents the user saw as "idle" really are `idle` in Herdr.
- **Events (verified on herdr 0.9.1, v0.0.25 fix):** agent status changes fire **no** global event; only `pane.agent_status_changed`, which requires a `pane_id` (so do `pane.output_matched` and `pane.scroll_changed`). Up to v0.0.24 we subscribed to it without one, so every `events.subscribe` failed (`missing field pane_id`) and the hub silently polled at 1.5s. One unknown pane id rejects the whole request (`pane_not_found`); a subscribed pane closing doesn't end the stream. `pane.updated` fires on every terminal-title change (agents animate titles), so it's not subscribed; `workspace.metadata_updated` is quiet and is.
- **Start Herdr environment (`serverEnv()`):** panes inherit the server's env, so it's started without VS Code/Electron variables and with Kiro's `Q_TERM_DISABLED=1` (unless `Q_TERM` is set). Without it Kiro's shell integration wraps every pane in `kiro-cli-term` (`zsh (kiro-cli-term)`), which hides agents from Herdr's detection: happened on the first real Start Herdr. A server started from a Kiro-wrapped terminal inherits `Q_TERM` and isn't affected. Verified from inside a pane (`pane.send_text` + `pane.read`); `ps eww` can't read pane shells' env on macOS.
- **Inside a Herdr pane, `HERDR_SOCKET_PATH` is set to the user's live socket and wins over `HERDR_SESSION`.** Claude Code here runs in such a pane, so `HERDR_SESSION=hb-x herdr …` talks to the **live** session: `herdr server stop` stopped it once (2026-10-19; agents in it were interrupted) and `npm run test:vscode` created its spaces there (now `run.ts` drops the pane variables and refuses a socket outside `sessions/hb-vsc/`). For any throwaway session set both `HERDR_SESSION` and `HERDR_SOCKET_PATH=~/.config/herdr/sessions/<name>/herdr.sock`, and stop its server by pid, never `herdr server stop`.
- **Never start a test server with only a different socket path** (`HERDR_SOCKET_PATH`): sessions are separated by *name*, so it restores the real session's state, resumes its agents and rewrites `~/.config/herdr/session.json` on exit (happened once). Always use `herdr --session <name>` / `HERDR_SESSION` for experiments. macOS caps Unix socket paths at 104 chars.
- **Learned by testing against a throwaway session** (`herdr --session hb-test server`, socket `~/.config/herdr/sessions/hb-test/herdr.sock`; use this, never the user's live session, to try mutating calls):
  - `agent.start` `name` must match `^[a-z][a-z0-9_-]{0,31}$` (names are CLI targets); we use `claude`, `claude-2`, … and show them as "Claude", "Claude 2".
  - A pane just created isn't at its prompt yet: `agent.start` answers `agent_pane_busy`; `startAgent` retries for up to 15s.
  - `agent.start` can report success for an agent that isn't installed (tried `muse`).
  - `workspace.close` on a space with linked worktree spaces needs `close_group: true` (error `workspace_group_close_required`).
  - `worktree.create` puts checkouts in `~/.herdr/worktrees/<repo>/<branch>`; `worktree.remove {workspace_id}` closes the space and deletes the folder (refuses with uncommitted changes unless `force`).
- **VS Code "+" (verified in VS Code 1.140's source):** a contributed profile is the default when `terminal.integrated.defaultProfile.<os>` equals its **title**; the setting is `restricted` (ignored in untrusted workspaces); profile terminals get their location from the clicked "+", so the provider must not set one; only user-created terminals use the default (extension-created ones don't). The hub window sets `defaultProfile.osx = "Herdr Shell"` at workspace scope once.
- `pane.read` results have `revision: 0` on 0.9.1, so `activity.ts` detects output changes by comparing text. Each socket request takes ~100ms; activity polls run 6 at a time.

After upgrading Herdr: `npm run gen:types`, fix compile errors, and save a new `herdr api snapshot` fixture.

## Herdr plugin facts (verified on herdr 0.9.1 with a probe plugin in an isolated `XDG_CONFIG_HOME`)
- Plugins are per **user**, in every session (`~/.config/herdr/plugins`). To test without touching the user's Herdr, set `XDG_CONFIG_HOME`/`XDG_STATE_HOME`/`XDG_DATA_HOME` to a temp dir **short enough for the socket** (≤104 chars on macOS: the scratchpad is too long, `$TMPDIR/hbx.XXXX` works), then `herdr plugin link`, `herdr --session <name> server`, `herdr plugin action invoke <plugin>.<action>`, `herdr plugin log list --plugin <id>`.
- Actions get `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID`, `HERDR_SESSION`, `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, `HERDR_PLUGIN_{ID,ROOT,CONFIG_DIR,STATE_DIR,ACTION_ID}` and `HERDR_PLUGIN_CONTEXT_JSON` (`workspace_id/label/cwd`, `tab_id/label`, `focused_pane_id/cwd/agent/status`, `selected_text`, `clicked_url`, `invocation_source`, `worktree`). ## Conventions
- **Security (from a commit review):** git runs only in trusted windows (Workspace Trust is the real boundary; the list below closes known routes but can't be proven complete), with `--no-optional-locks`, `core.fsmonitor=false`, `log.showSignature=false`, `protocol.allow=never` (no lazy fetch in partial clones → no core.sshCommand/ext::), `core.hooksPath=/dev/null`, every repo-defined `filter.<driver>` blanked (`filterOverrides()` fails closed: any config-read error other than exit 1, or an unexpressible driver name → skip git) and `--ignore-submodules=all`: a repo's own `.git/config` can otherwise make `git status`/`log` run programs (fsmonitor, clean filters, gpg.program). gitTest proves each vector stays off. git also runs without the editor's `GIT_*` environment (`gitEnv()`). `herdr.binaryPath`/`socketPath` are `machine`-scoped so a repository's `.vscode/settings.json` can't pick the program we launch. The hub is recognised only by its workspace file (`~/.herdr-cockpit/herdr-cockpit.code-workspace`), not by a `herdr.hubWindow` workspace setting alone. Keep these when touching git, settings or process launches; never put real paths, hosts, names or ids in tests/fixtures/docs (the repo was scrubbed once).
- TypeScript strict, `npm run lint` clean. Keep `herdrClient.ts`, `model.ts`, `connection.ts`, `hubFiles.ts`, `tools.ts` free of `vscode` imports so `npm test` runs without VS Code.
- The plugin stays POSIX `sh` (no bash-isms, no jq/node/python): it must run on any macOS or Linux box with Herdr. Test both shells. Its `alive` requires pid > 1 (`kill -0 0` / `-1` succeed).
- Deep links are an attack surface (any web page can open one): only ever select things the user already has; never run commands or change settings from a link without asking.
- Add a mock-server test for any new socket method.
- Never write workspace folder index 0.
- Agent processes belong to Herdr. **Since v0.0.35 the user's own close (the tab's X, exit reason `TerminalExitReason.User`) closes the pane in Herdr** per `herdr.closeTabInHerdr` (ask: idle shells at once, agents / busy shells (`pane.process_info` leader isn't a shell) / a space's last pane ask; Herdr closes a space with its last pane). Everything else only detaches: our own dispose (space switch, prune: reason Extension) and window close/reload (Shutdown). Never close panes from `Pseudoterminal.close()`, which can't tell these apart.
- **Hub offer on startup (v0.1.1):** after the first refresh, `maybeOfferHub()` asks "Open Herdr Cockpit here?" when `shouldOfferHub()` says so (hubFiles.ts): mode `emptyWindows` (default; no folder and no workspace file) / `allWindows` / `never`, never in the hub, never without a herdr binary, never while `hubOpen(scheme)` (status file fresh within 90s and its pid alive). Open Herdr Cockpit reuses an empty window (`openHub(false)`), else a new one.
- **Welcome page (v0.1.1):** `closeWelcome()` runs on every space switch: the tab API shows the editor's Welcome / walkthrough page as a tab with `input === undefined` (like other built-in editors) labelled "Welcome", so it's matched by label (`/^(Welcome|Get(ting)? Started)\b/`; English UI only). The hub workspace also gets `workbench.startupEditor: none` (new files, and once at workspace scope unless the user set it). In tests, close a specific tab with `tabGroups.close(tab)` (exit reason User, like its X): `show()` + `closeActiveEditor` can hit another group's tab.
- **Reopen Closed Tab (0.2.10):** VS Code's Reopen Closed Editor can't rebuild our tabs (the stream belongs to the extension), so `herdr.reopenClosedTab` keeps one history per window of closed Herdr tabs (`ClosedTab`, recorded in `closedTabByUser`) and `'editor'` markers for any other closed editor tab (`tabGroups.onDidChangeTabs`, filtered by `reopenableEditor()`: not terminal tabs, which aren't in VS Code's history, nor the `vscode-terminal:` text tabs `redrawUndrawn` closes or the Welcome tab `closeWelcome` closes, nor a tab that only moved group). The newest entry wins: a marker goes to `workbench.action.reopenClosedEditor`, a Herdr tab goes to `reopenTab()` (manage.ts): a pane still in Herdr is attached; a closed one is recreated next to its Herdr tab's remaining panes (`pane.split`), else as a new tab, else as a new space, and an agent restarts with the same kind and name, resuming via `resumeArgs()` (claude `--resume <id>`, codex `resume <id>`, only for an `agent_session` of kind `id`; on 2026-11-10 none of the user's live agents had one stored). The user binds it to ⇧⌘T and lists it in `terminal.integrated.commandsToSkipShell`.
- **Renames (v0.0.36):** VS Code has no terminal-rename event, but `$acceptTerminalTitleChange` updates `terminal.name`, so `AttachTerminals.pollNames()` (1s) compares each tab's name with the last one seen and the one we set: a difference is the user's rename → `pane.rename` (shells) or `agent.rename` with `agentSlug()` (agents). Herdr → tab renames go through `HerdrPty.setName` (`onDidChangeName`, no focus; the old `renameWithArg` focused the tab). **herdr 0.9.3 emits no event on `pane.rename`** (`tab.rename` emits tab.renamed; `pane.updated` only fires for title changes), so they arrive with the safety poll, now 5s while events are live (was 15s).
- **Split Terminal (v0.0.36):** profiles return a `HerdrPty` with a deferred target: on open it waits `PLACEMENT_MS` (150ms) and, if the active tab was a Herdr tab of the same space and a new editor group appeared, calls `pane.split {target_pane_id, direction: right}`; otherwise `tab.create`. VS Code opens an editor-area split of a contributed default profile at SIDE_GROUP (renderer source), which is what makes it detectable; panel splits (`splitActiveTerminal`) aren't, so they make new tabs.
- **Taken-over panes (0.2.2):** one controller per pane; `--takeover` ends the previous one with reason "terminal attach taken over", and Herdr never says who took it (no client info in the schema). Seen in real use with Cockpit windows in VS Code and Kiro both following Herdr: each space switch made them take the same panes from each other. Now `HerdrPty` falls back to `herdr terminal session observe` (read-only, its own size, ignores stdin, so resizes restart it; survives the controller releasing; closes when the pane goes) with a yellow bottom-row note (`Screen.toast(…, 'note')`, repainted after each frame since frames aren't written into the note) and takes control back on the first keystroke, which is **not** sent (it could answer an agent's prompt). Who has it comes from claims: a window writes `~/.herdr-cockpit/claims/<sha256(socket\npane)[:24]>.json` (`{editor, scheme, pid, at}`) **before** spawning its controller, removes its own on release/loss, and `pruneClaims()` drops dead pids on activation; `claimant()` names a live, newer, non-self claim ("Kiro", "another Visual Studio Code window"), else "another Herdr client". Follow-mode attaches are `polite`: a pane another live window claims starts read-only; losing one within 5s of a polite start is `expected` (no notification). User-initiated attaches (sidebar click, links) take back. Notifications are grouped per 600ms (`herdr.notifyOnTakeover`). `npm run test:vscode` covers takeover → read-only + name, typing takes back without sending the key, and polite follow.
- `npm run test:vscode` (src/test/vscode): real-editor integration test. Launches the installed VS Code as a separate instance (temp user-data/extensions dirs, temp HOME so its hub window is that HOME's ~/.herdr-cockpit) with the extension from source, against a throwaway `hb-vsc` Herdr session, and checks: space switch opens built-in tabs; the editor "+" makes a tracked built-in tab; double-click copies (clipboard saved/restored); the tab's X (`workbench.action.closeActiveEditor`; `terminal.kill` is panel-only) closes the idle shell in Herdr; rename both ways (`renameWithArg` = the tab's Rename; `herdr pane rename`, focus unchanged); Split Terminal splits the Herdr pane in the same Herdr tab; switching only detaches; a pane closed in Herdr closes its tab. Extension log lines are mirrored to the console when `HERDR_HUB_TEST_SESSION` is set. The suite runs in `herdr.windowMode` = `workspace` (set in the generated hub file): in folder mode Switch to Space asks "own window or this one?" and nothing answers it. On the user's Mac VS Code is in `~/Applications`, so run it with `HERDR_HUB_TEST_EDITOR="$HOME/Applications/Visual Studio Code.app/Contents/MacOS/Code"` (passed on 0.3.7, 2026-11-12). On macOS the editor starts with `--use-mock-keychain` (a fresh profile otherwise pops up a Keychain dialog that can hold the run). The test sets `herdr.followMode: true` (off by default since 0.3.x; step 7 follows a switch made in Herdr). A fresh editor can take more than 4s to confirm a folder was added, so `folders.ts` `update()` waits 10s and then checks the folder list itself. Herdr paints rows with real spaces, so `translateToString(true)` doesn't trim them.
